# Produktentwicklung

Im vorhandenen Projekt arbeiten, Branch/HEAD/Arbeitsbaum prüfen und fremde Änderungen erhalten. Native öffentliche APIs und tatsächliche Bibliotheksgrenzen prüfen; bestehender Produktcode und historische Berichte besitzen kein Vetorecht gegen Ersatz.

Nur notwendigen aktuellen eigenen Code behalten. Entfernte Funktionsketten einschließlich Aufrufern, UI, Tests und Abhängigkeiten tatsächlich löschen. Keine Adapterketten oder zweite Pipeline, keine historischen Testzahlen oder Quelldateilisten als Produktvoraussetzung.

Aktuelle Tests prüfen den neuen Weg und seine Fehlerfälle. Technischer Erfolg, wissenschaftliche Qualität und echte menschliche Prüfung getrennt ausweisen. Originale und bereits gespeicherte menschliche Entscheidungen nicht unbemerkt überschreiben. Keine historische Migration voraussetzen.

Abgeschlossene Schritte committen. Architektur/ADR beschreiben die entstandene Lösung, ACCEPTANCE die tatsächlichen Versuche, CURRENT_STATE die Übergabe. Historische Berichte/Gitstände bleiben Nachweise. Der aktuelle Nutzerauftrag bestimmt Datenfreigabe und Veröffentlichung.

Für R17 beginnt der Produktweg bei der nativen Konvertierung. Bildanreicherung, Evidenzextraktion und die Analyse von Beziehungen und Findings werden separat gestartet. Die Abnahme prüft Original, native Konvertierung, tatsächlichen Modellinput, Rohantwort, Validierung, Graph und fachliche Interpretation. Frühere Stände bleiben über Git und Workspace-Exporte nachvollziehbar.
